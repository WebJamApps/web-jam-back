# venue rules



- **MongoDB Update Operator Destination Validation on Guarded Fields**: When validating REST API payloads to prevent alternate update paths on guarded fields (such as `location`), inspect both keys and values of MongoDB update operators. Operators like `$rename` (`{ $rename: { source: destination } }`) take the target field name in the value rather than the key. A validator that checks only operator sub-keys misses `$rename` operations that target the guarded field as a destination (e.g. `{ $rename: { notes: "location" } }` or `{ $rename: { notes: "location.coordinates" } }`), allowing caller input to bypass validation and corrupt or clear the field via MongoDB's native rename semantics. Any write targeting a guarded field as an operator key or as a `$rename` destination (both whole-field and dotted paths) must be intercepted before reaching the persistence layer and refused with HTTP 400.


- **Mutual Exclusion, Lease Ownership Verification & Fencing for Full-Collection Upsert-and-Prune Refreshes**: When implementing background or CLI dataset refreshes that upsert a downloaded snapshot and prune records absent from that snapshot (`deleteMany({ id: { $nin: keptIds } })`), two overlapping runs or a slow/paused writer that outlives its lease can interleave upserts and prunes, deleting one another's records (leaving only the intersection or an empty collection when disjoint) or re-inserting pruned stale rows during the replacement's prune-to-commit window. Always enforce mutual exclusion and stale-writer fencing across the entire mutation phase: (1) in GitHub Actions workflows that support scheduled and `workflow_dispatch` triggers, configure a fixed top-level `concurrency` group across refs and triggers with `cancel-in-progress: false` so overlapping runs serialize rather than run concurrently or cancel an in-flight writer mid-refresh; (2) acquire a shared database lease/lock (via atomic `findOneAndUpdate` with `upsert: true`, TTL expiration `lockExpiresAt`, monotonic `lockEpoch` via `$inc`, and duplicate-key `E11000` refusal, scoped within the authorized collection so least-privilege database roles require no extra collection grants, and released via `findOneAndUpdate` setting `lockOwner: null, lockExpiresAt: new Date(0)` rather than deleting the lock document so durable epoch and timestamp metadata survive across runs); (3) verify and renew lock ownership (`lockOwner`, `lockEpoch`, and `lockExpiresAt > now` with `upsert: false`) after download, before every `bulkWrite` batch, before `deleteMany`, and after `deleteMany` before returning, persisting `lastIssuedAt` after download, `lastPruningAt` on the pre-prune lock check right after all `bulkWrite` batches have succeeded (before `deleteMany` starts), and `lastCommittedAt` on the final post-prune lock check; (4) fence `bulkWrite` `updateOne` filters and `deleteMany` prune filters by `downloadedAt: { $lte: downloadedAt }`, and roll back a superseded writer's `downloadedAt` rows when the shared database lock document records either a completed batch-write/prune entry (`lastPruningAt > downloadedAt`) or a completed refresh (`lastCommittedAt > downloadedAt`) — recording `lastPruningAt` after all `bulkWrite` batches succeed and before `deleteMany` starts closes the prune-to-commit window (where an expired writer finishes its delayed `bulkWrite` and its `catch` block after the replacement's `deleteMany` has already pruned the stale listing, but before `lastCommittedAt` is written), while still protecting against partial replacements that fail during `bulkWrite` before reaching the prune phase; never store refresh-progress state only in process-local memory (such as a `WeakMap` or module variable, which an independent CLI process cannot see or update) and never infer a completed replacement merely from the existence of rows with a newer `downloadedAt`; and (5) cover overlapping writers, expired-lease / replaced-ownership resumption, partial replacement failures, cross-process / isolated module-and-model instances, and the prune-to-commit window (pausing the replacement after pruning but before recording its commit) with regression tests.
